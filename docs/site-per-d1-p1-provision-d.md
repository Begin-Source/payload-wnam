# P1 D 站与普通分组发布

本轮目标是通过通用 `site:provision` 完成一个全新测试站的真实创建，再验证普通代码发布保留新增绑定。既有 C 站的完成回执继续保留，不能把其历史回执改写成每次发布的新版本。

## 固定请求与有效清单

`operations/p1-release.json` 明确选择 `operations/provision/p1-d.json`。D 站请求固定 operationId `d31f541a-f160-48dc-a992-57bf9da70344`、siteId `p1-d`、本地 ID 104、租户 2、负责人 7、`SITE_D1_D`、P1 group 1、schema 1 和 UTC。数据库名称由操作 ID 派生；不预猜 D1 UUID。生产开关保持关闭，账号仍为 P1 合成账号。

请求包含完整 A/B/C 原清单及其摘要，预期原分组 deployment 为 `0ffbeecb-db65-4ac1-8b17-52cafe7b1275`，对应实际读取的已有版本。创建前中央查询确认站点 ID、本地 ID、binding 和未完成操作均无冲突；运行时仍重新核验并在 SQL 中执行原子预约。

P1 发布先完成中央兼容迁移和中央角色更新，再运行通用命令的 `--dry-run` / `--apply`。本次不再调用旧 C 站专用部署入口。D 的持久建库回执提供实际数据库 UUID，受审核请求与该回执一起生成四站有效清单；普通发布和真实浏览器回归均使用同一份 `.cloudflare-ci/p1-effective-site.json`。

有效清单带当前 CI 提交、操作 UUID、D1 UUID和摘要；读取端重新从源 A/B/C 清单和明确 D 请求推导完整内容，拒绝改变原成员、任意添加服务/存储绑定或使用旧提交的文件。后续同一 P1 发布入口继续从请求和持久操作生成清单，不能退回旧三站清单覆盖 D。

## 中央 schema 与发布互斥

中央 schema v4 在已审核 v3 的完整摘要基础上仅新增 `site_group_leases`、`site_group_releases` 和 pending 索引。原始 v1/v2 数据库按既有迁移逐级经过 v3；每次升级仍核验完整旧 schema，并以同一 D1 batch 写入新增 DDL、迁移日志及 schema 回执。不改站点 schema 或既有建站回执。

新站预约与普通发布以同一个中央 D1 原子互斥：

- 普通发布领取租约时必须没有该组未完成的建站操作。
- 新站预约时必须没有该组有效发布租约或未核清的发布意图。
- 发布租约与建站执行租约合计最多四个，使用数据库时钟、180 秒租约和 30 秒心跳。
- 旧执行器不能续租、写入新回执、完成发布或释放继任者租约。上传结果不明的意图不随租约过期消失。

这些条件在实际 INSERT/UPDATE 中重复校验；预览不是锁。人工直接在 Cloudflare 控制台改资源仍需由运维核对快照和部署来源，不能视为受此应用日志管理。

## 普通发布回执与恢复

普通发布使用独立于建站操作的确定性 releaseId，由组、提交和清单摘要计算。上传前保存原 deployment 和完整目标清单，上传变量包含 `RELEASE_OPERATION`。只有实际 deployment/version、提交、清单摘要与该标记吻合，才能保存上传回执；未知结果不会因为超时或重跑而重复上传。

原生绑定核验与完整四站浏览器验收通过后，才保存完成时间。发布失败后，已上传 Worker 不会自动回滚；待完成记录阻止继续覆盖。后续 CI 可以在证明旧上传身份和清单一致的前提下补完旧验收，再发布当前代码；该恢复分支没有上传旧代码的能力。实际来源无法证明或目标清单不同的情况仍要求受控处置，不自动抹去 pending 记录。

首次普通发布在 CLI 上传成功、回执保存前注入异常，再以新执行器恢复。这是明确的异常注入，不是实际网络丢包。完成后再次调用只核验现有部署和回执，不重复上传或重跑已通过的浏览器验收；发布租约本身仍会正常领取/释放。

## 真实验收范围

通用建站命令先验证 D 的绑定、schema 所有权、租户/负责人投影与真实域名，再经中央表单登录和选择器进入 D 的原生编辑页。普通发布后，四个独立 D1 使用同一分类 ID 990001 并发读写；验证 C、D 分别撤权时其他三站保持可用，并保留原生命周期、MCP、host-only Cookie、移动端和退出测试。

原生 D1 集成测试覆盖建站/发布同时竞争、租约过期后 pending 意图仍阻止新站、旧执行器写入/释放被拒绝、上传回执恢复、未知结果不重放、失败验收继续及跨两类操作的四并发限制。Cloudflare 创建/上传的实际结果与这些受控回调测试分开记录。
