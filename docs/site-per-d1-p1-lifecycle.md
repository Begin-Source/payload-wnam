# P1 站点暂停与恢复

本轮实现中央站点管理 API、站点经理操作界面及独立中央 D1 的版本化增量迁移。云端构建、完整 Worker 检查与远程验收尚待运行；不能据此标记 P1 通过。

## 管理行为

- `GET /auth/site?siteId=p1-a`：只从中央注册表读取当前状态、路由/schema 版本、生产开关及当前员工角色。必须提供唯一明确的 `siteId`，且仍有该站授权。
- `POST /auth/site-lifecycle`：请求 JSON 严格只接受 `siteId`、`action`（`pause` / `resume`）、`expectedRoutingVersion`、`operationId`。中央登录必须有效，且当前员工有该站 `manager` 授权；全局管理员角色不能替代站点授权。
- 操作 ID 为 16–128 个字母、数字、下划线或连字符，以字母或数字开头；界面使用 UUID。同一员工使用相同操作 ID、站点、动作、预期版本重试，返回原回执，不再次修改状态。操作 ID 换目标、换动作、换员工或换预期版本均拒绝。
- 只允许 `active → paused` 和 `paused → active`。迁移、准备和停用状态不受此入口修改；版本冲突返回 409。缺少有效中央会话返回 401，缺少站点经理权限返回 403，参数错误返回 400，服务异常返回 503。
- INSERT 本身验证原中央会话的有效期、账号锁定与经理授权；同一 SQLite 语句的触发器完成路由 CAS、递增版本并删除该站旧票据/会话。更新失败，操作回执一并回滚。其他站的路由、会话和数据不变。
- 暂停后，现有站点入口拒绝后台请求；恢复后仍须从中央重新进入，旧 Cookie 不会复活。生产开关不被自动修改。P2 尚未实现，不能把此入口表述为已经完成生产任务排空或供应商取消。
- 中央页面沿用原生 Payload 组件和主题。经理可在行内确认暂停/恢复；取消不提交。网络结果不明时保留同一操作 ID，提供重试或刷新；过期会话、撤权、状态冲突分别显示恢复路径。普通员工仅保留进入站点功能。
- HTTP 写入仅接受部署所选中央 origin，JSON 上限 2 KiB，不信任 Content-Length、转发主机头或请求体身份。所有响应 private/no-store。

## 现有中央 D1 的增量迁移

目标为已部署的 `payload-wnam-p1-central`，ID `c1e4ef96-e6ca-4457-93b3-55af5b572c0d`。只从已完成的 `p1-central-schema-v1` / 摘要 `32d9ac67f25b2dec5326ed868a1e98c5b06e0de87d5312c3b69d8591507604a3` 升级到 v2，新增：

- `site_lifecycle_operations`：动作、目标、操作人、预期/结果路由版本与执行时间。
- `site_lifecycle_apply`：原子路由改变和旧会话撤销触发器。
- `site_control_schema_migrations`：来源摘要、目标摘要、操作 ID 与时间。

升级前核对完整旧 schema，并验证新产物除这三个对象以外仍为原摘要。新增 DDL、迁移历史和初始化回执推进在一个 D1 batch 事务中；任何 SQL 失败全部回滚。响应丢失后的重试依据目标摘要恢复，不重复升级。不允许借迁移绕过未知对象、旧 schema 漂移或删改现有字段。两个站点 D1 保持原 v1 schema。

重复初始化保留已登记站点的生命周期状态和路由版本，并核对固定 D1、binding、分组、schema、时区及建站操作等信息，不把版本重置为 1。专用合成用户 7 的两站授权改为 `manager`，仅供该隔离环境验收；这不代表真实员工交接完成。

## 验证范围

新增原生 D1 测试覆盖重复/竞争操作、跨站/跨用户回执冲突、权限降级、提交瞬间撤权/会话过期、异常回滚、明确目标与 HTTP 边界；迁移测试覆盖已存在数据保留、漂移拒绝、事务失败与响应丢失恢复。

Cloudflare 中的完整中央 Worker 浏览器检查和真实 P1 HTTPS 检查调用同一验收脚本：经理按钮、取消、手机确认布局、暂停、幂等重试、旧版本冲突、恢复、后端已成功而界面收到 503 的重试。远程检查额外验证旧站点 Cookie 失效、B 站可用、A 站重新进入，以及原有撤权/退出检查。失败恢复必须证明暂停操作属于本次检查，再使用一个固定操作 ID 恢复；不能覆盖其他路由变化。

这里只完成生命周期这一部分。MCP、通用建站、后台队列/主数据投递、邮件、P2–P5 及完整运维命令继续待实现。

事务语义依据 [Cloudflare D1 batch 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)，实际行为仍以本轮云端原生与远程验收为准。
