# 当前站点只读核验

`site:verify` 独立于历史建站请求，使用当前完整分组清单和明确的站点列表。它不创建数据库、不迁移、不修改权限、路由、内容、任务或建站回执。只在 Cloudflare Builds 检查通过后的环境执行，本地不安装依赖、不运行测试或此命令。

```sh
pnpm run site:verify --request .cloudflare-ci/site-verify-request.json
```

## 输入、归属和实际绑定

请求严格包含核验 operationId、中央/当前分组清单、两个 Worker tag、固定账号/区域、目标 schema 摘要、预期实际 deployment，以及每个目标 siteId 的数据库所有权凭证。不能传 SQL、凭据、任意脚本路径、apply 或 force 开关。目标必须在当前分组中；完整清单不能遗漏中央登记成员，服务绑定/R2/域名不能增加未审核能力。

`operations/p1-verify.json` 明确列出 A/B 的原始 P1 schema 凭证和 C/D 的原始建站操作。旧式凭证只允许对应 P1 A/B，不可用它接管其他库。P1 云端控制器从审核过的四站有效清单生成本提交的核验请求，实际分组 deployment 也必须匹配。

新增内部 `verify(siteId)` 使用分组 Worker 中的实际 D1 binding 读取本地站点，再前后核对中央路由。它不要求历史站点等于分组最近一次新建站点，不要求 users 只有一行；暂停站点也可以核验。公共 HTTP 不挂载此能力，调用方不能选择 SQL、本地记录 ID 或任意 binding。

维护端独立核对中央站点/租户映射、本地租户来源、身份投影指向的中央用户、实际 schema 完整对象及初始化凭证。核验前后复查路由和 deployment，变化时拒绝出具通过结果。

## 数据、媒体和任务检查

对审核 schema 中的每个表按 rowid 分页读取，每页 50 行，记录行数及逐行内容哈希，不输出正文或用户行。主记录、数组/关系表、版本历史、运行状态和任务表均在库存中；拒绝额外/缺失 schema 对象、错误站点记录及任何非空站点归属字段指向别站。执行原生 `PRAGMA foreign_key_check` 检查声明的 SQL 外键。

当前请求使用本提交生成的同一份站点 schema 产物；历史版本产物选择、混合 schema 版本核验和 WITHOUT ROWID 表的主键游标尚未接通，遇到不支持的结构会拒绝通过，不跳过该表。内容哈希用于当前库库存，不能直接当作跨库迁移的规范化主键排序哈希。

公开 media 和 private_media 分别读取本组对应 R2 桶中的 `sites/<siteId>/...` 对象，拒绝路径越界、缺失对象、大小不一致及截断流，按实际字节计算摘要。已撤回的版本媒体必须不存在或带撤回标记。尚无 filename 的待生成记录单独计数，不将其当作已有文件验证；当前单对象核验上限为 64 MiB，超过即失败。未列入数据库的孤立 R2 对象不在本命令的清理范围。

任务表与子表参与完整内容哈希；JSON 中显式的 siteId/localSiteId 不得指向别站。这个检查不运行任务，也不证明尚未实现的 P2 调度、供应商额度和生产吞吐。

媒体检查前后分别做一遍完整数据库库存；两次内容哈希不同即拒绝通过，要求重试或先冻结。两次一致是稳定读取证据，不是跨库事务快照，也不能排除在两次读取之间发生后又恢复的修改。迁移时仍须按完整计划冻结并与源库比较，不能只凭健康检查宣称 ID/URL/时间/关系已完整迁移。任意 HTML/SVG/JSON 内嵌引用的完整数据图核验仍待迁移阶段接通。

## 发布门禁和证据

P1 普通分组发布在四站浏览器检查后运行此命令，所有站点通过后才完成发布日志。失败保留 pending 发布并继续原记录恢复；不自动回滚或重传。只读命令本身不占写入租约，P1 调用时由外层普通发布租约维持组互斥。

报告写入云端 `.cloudflare-ci/verify/<operationId>/report.json`，按站点输出元数据、每 10 张表一段库存以及最终摘要/覆盖边界，等待 stdout 写入完成再退出。每段带 operationId/siteId/offset，避免完整报告作为超大单行在日志中丢失。该只读命令目前从头重读，可安全重试；没有声称存在持久分段核验检查点。
