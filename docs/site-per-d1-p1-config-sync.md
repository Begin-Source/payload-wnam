## 同步范围与授权

`configSnapshot.ts` 使用独立、有限字段的配置协议：`llm-prompts`、`prompt-library`、`pipeline-settings`、`quota-rules` 和 `site-quotas`。Global 发布要求中央全域管理权限；站点配额允许有对应租户权限的总经理发布，通过真实中央 Payload 读取权限验证源配额和 Site。配额同时绑定稳定 siteId、租户及源记录 ID；不会将中央数字 sites.id 作为本站外键。

LLM provider/key routing notes、配额备注、`usageYtd`、提示词数组行 ID 均不进入传输字段。配置 JSON 中显式凭据键会拒绝；运营仍不得将凭据放入提示词正文。各配额数值必须明确、有限且非负，计数配额必须是安全整数。未随此功能修改共享配置原有默认政策；每站每日 10 个目标仍由后续 P2 调度与正式政策选择实施。

中央修订只追加，以预期修订和操作 ID 处理并发与重试。成功重试仍经过当前源权限与归属检查。导出校验目标注册状态、路由版本和当前租户，并在读取后再次核验。`readConfig` 是待接正式认证传输的显式能力；摘要不代替调用方认证。

本站候选只写入 `site_config_releases`，接收新版、重复投递或晚到版本都不会改动运行配置。接收在同一 D1 batch 中核验本站 Site→Tenant 中央映射。应用需要本站 manager 明确调用，并引用已经接收的版本。

## 审阅、应用与回滚

`reviewSiteConfig` 返回配置内容和审阅摘要；摘要覆盖当前数据库字段、来源版本和有序提示词子行。它不只依赖毫秒级更新时间。`selectSiteConfig` 在提交时以 SQL 再次比较这些值，防止审阅后、校验后或同一时间戳内的编辑被覆盖。发现多个当前单例行会拒绝，不能随意选一条。

当前 Global/政策字段、提示词数组替换和操作回执在一个原生 D1 batch 中提交。字段采用实际清洗后 Payload schema 校验；只支持已知标量/JSON 和明确的提示词数组存储结构。任何父行或子行失败都会回滚，失败操作可准确重试；已完成操作重试不会恢复后来被替换的旧版本。同一审阅状态的竞争应用只有一次可以成功。回执保存操作者、目标引用、审阅摘要和此前可同步字段，便于审计；正文之外的 provider notes 不写入该回执。

应用保留当前记录 ID、创建时间及未同步字段。提示词数组使用新的本站行 ID。站点配额只更新政策和来源字段，保留本站 site/tenant 关系、备注和 `usageYtd`；用量不参与策略内容同步。普通站点 API 仍不能修改只读政策。恢复旧政策或 Global 必须再次审阅当前状态并明确选择旧候选；不会静默回退。
