# P1 独立中央配置与成本对账

状态：中央 factory、成本账本和财务保存路径已实现，使用隔离原生 D1 验证。尚未挂载正式中央角色；来源导出/消息投递、主数据同步、正式迁移与角色构建仍未接入，P1 未验收。

## 中央配置

`src/site-control/config.ts` 显式接收中央 D1、中央 R2、Payload secret、模型列表与 AI 授权能力。初始化不读取旧共享配置，不查库、不 seed、不发现远程模型、不自动迁移。保留中央凭据/会话、组织及租户隔离、联盟收益与佣金、公共主资料和公司知识；中央不注册文章、页面、分类、站点设计版本、原创证据或站点生产任务。

作者主资料去除本站 sites/expertiseAreas 关系，保留 GDPR 校验；商品去除本站分类、展示位置和 Review 草稿；公司知识去除本站分类/站点关系。中央媒体要求认证及租户访问，站点媒体通过独立站点配置管理。所有定义先克隆，避免 sanitize 或插件污染另一角色。

中央 Sites 使用不可重指向的 `runtimeSiteId` 对应注册表；新建/删除通过显式 provision/retire 流程，不能用通用 CRUD 绕开。已去除站点级联删除、设计镜像同步及本站资产关系；PATCH 保留原域名等默认字段。域名、操作人及运行状态的普通字段写入关闭，后续接入中央控制能力。该 factory 不开放匿名账号创建，仍支持原中央密码登录。中央 Payload 的操作拒绝在站点 ALS 请求中执行。

用户账号自助修改不再授予财务或组织管理权：分成比例使用现有财务写权限，租户/组长/运营经理归属使用组织管理角色，并继续受 Users 集合的可管理用户范围限制。站长不能通过编辑自己账号提高分成或转入另一租户。

旧共享后台的统计/批量动作组件会查询本站数据，未复制到新中央界面；正式管理动作、汇总视图与 MCP 显式站点能力仍须接入，不能把默认集合表单视为操作界面已完成。

## 成本账本

`costSchema.ts` 为显式中央迁移；依赖中央 users/tenants 和 site_runtime_registry，不会在请求或 factory 初始化时执行。

- `costLedger.ts` 接收经调用方认证的稳定 siteId，与事件 siteId 一致；当前只提供内部函数，没有浏览器写入端点或账户管理令牌。
- 事件使用 `{siteId, collection, recordId, kind, revision}` 唯一标识。recordId 为规范字符串，kind 区分 AI/DFS；金额是整数微美元，员工和租户均为中央 ID。事件为文档累计成本快照，不能把增量费用直接当作累计值投递。
- 同一修订不同内容拒绝；重复及乱序消息不重复计费。不可变事件与最新投影由一次 D1 batch 原子写入，投影失败同时回滚事件。更高修订可纠正成本、员工及租户归属，旧事件保留。
- 结算沿用既有按文档创建日期归属成本期间的口径；它不是按供应商扣款日期记账的现金账本。已删除源文档的历史成本也必须由来源导出保留，不能因内容删除丢失成本。
- 对账须提供全部注册站点（含零成本来源）的独立导出证明。摘要绑定站点、中央员工、租户、期间、记录及修订，无法把另一租户/期间的零值证明复用过来。未确认费用、缺项或摘要不同均不产生可用结果。
- 对账只分页读取中央 D1；不在财务请求中扫描各站 D1。生成证明时用全局 ledger epoch 作 CAS，避免读到混合修订；新增注册来源也会使旧覆盖证明不可用。成本变化通过 D1 trigger 使相关员工/租户/期间的证明失效，未受影响期间保持有效。

来源 exporter、authenticated RPC/queue、outbox watermark、实际供应商确认、每日重对账和归档尚未接入。`sourceRevision` 目前是独立来源证明的审计标识，摘要在中央核对，但内部函数不能替代未来传输入口的来源认证。当前测试手工提供独立 fixture 证明，不能声称真实费用流已经上线。

## 财务保存

`commissionStatement.ts` 替换新中央角色的旧结算 hook，直接读取已对账中央成本，不查询 articles/media 或站点 D1。收益查询按租户、员工和完整期间分页，超过 500 行不会静默截断；AI/DFS 是否计入由现有规则分别决定。员工、收款人、租户归属及分成比例必须有效，保留组长与运营抽成关系。

没有有效证明时拒绝保存结算草稿，不以零成本继续计算。即使规则排除某类成本，也保留完整来源证明与规则快照。批准前重新计算；已批准金额及依据不可直接修改，需要先返回草稿；付款必须来自已批准状态，已付款不能重新打开。

完整来源清单保存在中央内部对账表；员工可读结算单只保存证明 ID、金额、检查时间与来源数量，避免通过结算详情暴露其他租户的站点标识。

Payload schema 增加只读 `costReconciliationId` 和 `settlementEndExclusive`。部署时须在该 schema 后显式安装 `centralCommissionGuardSchema`；原生 D1 trigger 在批准/付款实际写入时再次检查证明，堵住 hook 读取后成本发生变化的窗口。历史已付款记录保留原依据，允许维护支付备注等元数据；后续成本修订需进入人工复核/调整流程，该操作界面仍待实现。

这是中央成本依赖改造，不代表收益导入去重、最终供应商账单确认或完整 P3 财务对账已验收。旧共享配置继续使用原结算路径，没有自动修改线上结算结果。
