# 多请求分组清单与发布协调

`operations/fleet/p1.json` 明确列出 P1 分组、A/B 原始 schema 所有权凭证，以及 C、D 两份不可变建站请求。维护端按顺序读取中央日志，将每一步的已建库 UUID 合入下一份清单；历史请求只作为来源证据，不能把 C 的三站清单重新上传覆盖当前四站。

`resolveProvisionFleet` 支持一次明确选择至多 20 组、每组至多 50 站的清单解析；这些是输入上限，不是已验证的生产容量。每个组必须有完整的已完成建站历史。除原始 P1 A/B 外，所有成员均来自所列的建站操作，不能把来源不明的数据库作为“历史基线”导入。新分组可从空基线及其首个已完成操作开始，Worker/D1 等资源仍须由原受限建站流程准备，本模块不会创建它们。

## 证据与隔离

解析器核对存储计划与输入完全一致、checkpoint 6、没有未完成步骤、六步回执齐全；数据库、schema、资料归属、原部署清单摘要、核验部署与激活站点相互对应。它再用中央登记逐项核对当前 D1/binding、站内 ID、schema、分组和可信后台域名。登记版本不能早于激活回执。暂停站可保留，迁移中或已退役成员阻止普通发布。

历史顺序不可跳过或重排，下一操作的基线必须与前一操作的结果完全相同。跨组重复站点、数据库、站内 ID、Worker 或 Worker tag 一律拒绝；公开/私有桶可按全局稳定 siteId 前缀跨组共享，但不能交叉充当另一种角色，也不能指向中央存储。混合 schema 版本及来源迁移需另接渐进迁移流程，不能放宽这些核对。

解析仅使用中央只读查询，不对历史请求、回执、路由、权限或数据库内容做修改。每组输出当前清单、摘要、各站核验凭证以及各原始操作的计划/回执摘要。部署控制器在上传前重读并核对同一结果，实际 API 资源和 runtime binding 校验继续由既有控制器执行。

## 逐组发布和恢复

`releaseProvisionFleet` 按明确顺序调用原有持久化组发布器。每组独立保存上传结果并验收，成功结果立即交给报告回调；中间组失败即停止后续组，不假设多 Worker 存在原子事务。重入复用之前已完成组的回执，恢复失败组的同一次上传，不重复上传已知结果。建站预约、发布互斥、180 秒租约/30 秒续期和四个运维租约总上限继续由中央日志执行。

已部署的 P1 控制器使用静态解析器和发布协调器，只选它现有的一个四站远程分组。它核对最后的 D 请求与部署入口一致，四站核验目标由历史清单生成并与显式目标文件比较。下面的新动态发布代码仍在验证分支，尚未替换该远程版本。

## 动态申请进入普通发布

验证分支的 `ci-p1-group-release.ts` 现改用 `resolveAdmissionFleet`，从 C/D 审定起始历史接入中央已完成申请。D 文件保留为原始审定锚点，不再充当“最新请求”。每次上传前重读完整历史/登记，检查所有当前 D1 与资源；最近请求决定 provision 来源标记，普通 release 仍有独立的操作 ID、租约和回执。

发布前后的固定 D `site:provision` 重入已从普通发布路径移除。当前四站初始创建已经完成；普通发布要求这一历史和后续申请都已完成，不再用旧维护请求去核验或覆盖扩站后的清单。恢复旧操作仍可使用明确审定的运维命令，不能将历史基线重新上传。

`fleet-artifact.ts` 为云端进程生成与提交匹配的完整历史交接文件。它包含所有原始请求、各实际数据库 ID 和最终清单；消费者使用同一严格解析器重放历史，核对审定前缀、基线链、账号/中央能力、Worker、schema、跨组身份和最终清单摘要。遗漏新增请求、修改旧请求、换组、换绑定或混入凭据均拒绝。该文件是已核对中央日志的控制器输出，不代替实际 D1 回执、登记或远程部署证明；上传前仍重读中央状态。

`p1EffectiveManifests`、部署末尾域名核对和后台 smoke 改为异步读取同一交接文件。plain Node 脚本通过已有固定版本 tsx 的[限定范围加载接口](https://tsx.is/dev-api/ts-import)复用 TypeScript 校验器，实际读取时才加载工具。没有安装新依赖或升级框架。完整站点核验目标由动态历史生成，原 A/B/C/D 所有权仍必须逐项保留，新增成员也必须进入核验目标。

普通发布的运行检查现逐站使用 `inspectSiteRuntime`，核对当前绑定、域名、路由版本、状态和普通发布标记；核验期间中央登记或部署变化即拒绝。它不再调用仅适用于初始化的“恰好一个身份投影”检查，已有多名员工登录不应阻止代码发布。运行检查允许暂停状态，P1 整套浏览器 smoke 仍使用合成员工 7 和可进入的测试站点；不能据此宣称任意真人负责人或暂停站的整套发布验收已经完成。

这次改动没有启用动态申请执行或自动构建派发，也没有执行远程 v5 迁移。下一次普通运行代码发布前，仍须移除旧的仅恢复选择，不能改摘要以保留与新源码不同的旧代码。P1 远程控制器仍只管理一个明确审定的组；多组能力目前由原生 D1 与受控外部上传测试覆盖。
