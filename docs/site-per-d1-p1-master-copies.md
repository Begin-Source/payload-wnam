# P1 主数据副本应用与提示词选择

状态：八类候选应用为真实 Payload 副本、稳定版本映射及提示词明确启用已实现，使用完整独立配置和双原生 D1 验证。正式 RPC/队列、应用与审阅界面、独立角色入口和远程迁移尚未接入，P1 未验收。

## 原子应用

`applyMasterRelease` 要求独立站点 manager、可信请求上下文和已配置的中央租户映射。只读取本站已接收的不可变候选，核验摘要、租户及完整依赖图；每个版本有独立的本地 ID。联盟、社交平台、布局、作者、Offer、方案、关键词预设和提示词均写入实际 Payload 表，外键绑定确切依赖版本的本地 ID。

这是限定字段和存储类型的导入协议。先运行已清洗 Payload schema 的字段校验及作者 GDPR 业务校验，再把父行、关系行、版本映射和操作回执放在一次原生 D1 batch 中提交。未知字段、新增但不支持的子表存储类型、无效字段和跨租户依赖会拒绝；不是通用 CRUD/hooks 执行器。任一步失败则全部回滚，相同操作 ID 可重试；相同 ID 的不同请求会拒绝。回执保存请求摘要、明确请求内容、操作者和提交状态。

新副本 slug 增加中央记录与版本后缀；Offer 默认 draft，方案不设为默认，提示词默认不启用。作者关联本站。已存在的同版本副本直接复用，保留员工改动。新版本不会改变已发布文章、URL、日期、分类、Offer 展示位置、文章方案快照或站点已选方案。

`site_master_copies` 的版本→ID 映射不可修改/删除；Payload hook 和数据库 trigger 防止删除副本或替换、移动来源身份。ID 水位表在显式迁移时从现存最大 ID 建立，此后由插入/ID 更新 trigger 保留最高观察值，副本分配器因此不复用迁移后观察到的已删除高位 ID。实际 Payload D1 schema 没有 `sqlite_sequence`；该机制不能恢复安装前已经删除的历史 ID，也不改变普通 Payload 创建的 ID 分配器。

## 明确选择提示词

`selectMasterPrompt` 要求目标更新时间，以及当前启用记录的 ID/更新时间（无记录时必须明确传 null）。以 tenant/key/profile 为槽位，在同一个 D1 batch 中关闭旧版本并启用目标。竞争选择只有符合已审阅状态的一次成功；失败会保留旧选择。完成操作的准确重试不会重新启用已被后来选择替换的版本。数据库唯一索引保证同槽位只有一个启用版本，通用 Payload 写入不能修改只读启用字段。

本地新建提示词保留原有立即可用行为，但已有启用记录时必须显式选择替换。旧模板正文不会删除。独立站点读取只取启用模板；中央/共享配置保持原查询范围。域名、分类槽位和信任页包三个全局入口统一调用公共读取器，限定 `pipelineProfile=null`，不再误选限定方案的记录。

文章和其他表单中的方案/预设选择器按本站登记租户筛选；不依赖站点表单不可填写的租户字段。

## 验证与剩余范围

`masterCopies.int.spec.ts` 覆盖八类真实副本及驱动类型、并发幂等、字段/GDPR 验证、失败批次全量回滚和重试、权限与双站隔离、身份不可改写、提示词 CAS/竞争/失败回滚、全局读取入口、已发布内容与展示位置不变，以及删除后的 ID 水位。`siteConfig.int.spec.ts` 继续覆盖完整独立站点的编辑、发布、权限、R2 和插件边界。

副本 DDL 只在隔离原生测试中显式安装，在独立 Payload schema 和候选表之后执行；没有自动启动迁移。资产复制/撤回、Global 与配额版本、正式投递认证/队列回执、审阅界面、角色构建/入口/类型生成和部署仍待完成。P0 云端回归继续使用共享配置，不代表独立站点已正式上线。
