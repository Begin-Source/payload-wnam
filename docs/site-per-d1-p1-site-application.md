# P1 独立站点应用

目标仍为完整执行计划，本文只说明独立站点应用的实现与验证边界。尚不代表 P1 放行、正式角色远程部署或生产迁移。

## 请求与身份边界

- `roles/site` 提供独立 Payload `/admin`、REST 路由、组件映射和 Worker 入口。中央和站点分别构建，不挂载旧共享应用的自定义 HTTP 控制器。
- 分组部署清单 `SITE_ROUTES` 明确稳定 `siteId`、保留的本地数字 ID、D1 binding、数据库 ID 和 schema 版本，每组最多 50 站，拒绝重复数据库或 binding。
- `SiteRoutingService` 是中央内部 named RPC，仅返回所属分组的注册元数据，HTTP 返回 404。每次后台请求核对注册表与部署清单，不使用客户端站点头选库，也不在中央不可用时回退到缓存权限或默认 D1。
- 请求在不可变 ALS 上下文中运行，通过现有严格 D1/R2 代理复用一个站点 Payload 实例。观察到路由升级、暂停或不可用后，本 isolate 的旧上下文失效；不将这一点描述为跨 isolate 的全局原子事务。
- 仅规范 HTTPS CMS 主机进入站点后台。所有普通写请求要求同源；票据兑换只接受中央来源。认证和后台响应不进入公开缓存。公开网站入口与缓存仍属于 P3 的待完成工作。
- 每次后台请求都实时验证中央会话和站点授权；Payload 自定义策略再次核验并加载不含密码的本地身份投影。`/me` 显式返回本次策略的站点、角色和安全身份字段，不依赖数据库里保存的旧角色，不签发站点 JWT。
- 原生 Payload 退出流程的 `POST /api/users/logout` 撤销中央站点会话并清除 host-only Cookie。独立表单退出入口执行相同撤销后跳转中央。退出不依赖活跃站点路由，因此暂停或撤权后仍可清除浏览器凭据；中央不可用时清 Cookie 并返回 503，不宣称远程撤销已成功。

## Cloudflare 验证

`scripts/ci-role-build.mjs` 在 Cloudflare Builds 分别生成两个角色的绑定类型、组件映射与完整产物。绑定 ID 为显式合成 ID；不能用于正式远程部署。依赖安装、类型检查、所有测试和构建都在 Cloudflare 执行，本地只编辑及做语法/差异静态检查。

`scripts/ci-role-site.mjs` 将完整中央 Worker、完整分组站点 Worker、3 个合成 D1 和 4 个 R2 放入同一原生 workerd 环境，使用 Chromium 实际登录中央并提交站点进入表单。验证范围包括双站独立 Cookie、完整后台编辑器、同 ID 内容的并发读取和独立更新、即时撤权及原生退出会话撤销。中央站点选择器界面仍待接入；测试中提交真实表单不等于选择器产品界面已完成。

锁定的 Miniflare `4.20260430.0` 为多个资产根目录使用同名内部磁盘服务。两个应用的 `BUILD_ID` 等文件不能合并。多 Worker fixture 校验精确版本及唯一源码匹配后，加载仅将内部资产磁盘服务名称加上 `workerName` 的临时副本，使每个角色继续使用自己的完整资源目录、原生 Static Assets 路由和绑定。此副本仅由该云端测试进程加载，不覆盖已安装依赖，不更改框架版本、其他检查或线上产物。
