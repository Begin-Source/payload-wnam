# P1 C 站分组部署、验证和激活

本阶段沿用 C 站原操作 `f8d779c3-12a4-491c-b368-00f274be2bfd`，继续 checkpoint 3 之后的 deploy、verify、activate。它不替代完整执行计划，也不表示通用建站命令、中央建站入口或 P1 其余项目已经完成。

## 部署与恢复

源清单 `roles/site/wrangler.p1.jsonc` 纳入 C 的固定 D1 与后台域名；正常发布不再以 A/B 清单覆盖 C。历史基线只供原计划摘要校验与 A/B bootstrap 使用，不能再作为站点 Worker 的部署清单。既有角色构建、前置资源核验、HTTPS 就绪与域名归属检查仍保留。

受限云端入口 `scripts/ci-p1-provision-finish.ts` 读取中央保存的原计划，核验 Git 提交对应发布 marker、账户、Worker tag、完整绑定集合、兼容设置和公开入口关闭状态。它复用本次通过构建检查的站点产物，保留已有站点密钥，不通过另一次 secret 部署拆分代码和绑定回执。

`finishProvisionedSite` 在上传前记录持久意图。部署配置带有操作 UUID、清单摘要和源提交编号；保存实际 deployment/version/commit 回执。上传结果不明时只核对实际部署的来源与完整清单，不自动重传。已有回执指向的版本若发生变化则拒绝接管；此时须受控修复，不覆盖旧回执或把未知结果当作失败后可重放。

首次实际演练在 CLI 上传成功、中央回执未写入时主动抛出异常，再以另一执行器调用恢复。该演练不是实际进程终止或真实网络丢包。未知上传尚无匹配来源证据时，原意图保持 pending，不执行第二次上传。

## 激活前后的验证

站点 Worker 新增命名内部服务 `SiteProvisionInspectionService`，默认 HTTP 入口不暴露该能力，命名服务的 fetch 也返回 404。服务只接受明确站点与操作 ID，从固定清单选取绑定，并核对中央路由、schema 所有权、站点记录、租户和负责人投影；不接受 SQL、数据库名称或任意本地记录 ID。

云端维护代理通过远程服务绑定调用实际 Worker，验证其返回的发布提交与部署回执一致，再核对域名归属和真实 TLS/HTTPS 响应。C 仍在 provisioning 时应返回 503，不能把这个状态当作可登录。该步骤完成后才允许进入激活。

激活写入受中央操作租约、预期路由版本、站点归属、负责人权限和 verify 检查点约束。路由状态/版本改变与旧票据、会话清理使用同一 D1 batch。随后实际 Chromium 从中央密码登录、选择 C、兑换票据并进入原生编辑器；三个独立库使用相同分类 ID 并发读写，验证跨站隔离、伪造站点头、host-only Cookie、站点密码登录拒绝、C 即时撤权和移动端。原 A/B 生命周期、MCP、撤权及退出检查继续执行。

如果激活后的验收失败，执行器在持有有效租约且路由未被其他操作者改变时，将 C 退回 provisioning 并再次增加路由版本、清理会话。恢复保留待完成的激活意图；下一次运行重新验证部署和绑定，再继续验收。人工暂停导致版本改变时，执行器拒绝覆盖它。

只有实际验收成功、最终路由和部署再次核对一致后，才保存激活回执、推进 checkpoint 6 并释放未完成建站的分组占用。后续普通代码发布保留 C 清单，不重置历史建站回执或站点路由版本。

## 测试边界与剩余工作

新增七项集成检查使用原生 D1 日志/路由和可控部署回调，覆盖只读预览、回执丢失后的单次上传恢复、无来源的未知结果、错误绑定/版本、激活失败恢复、人工暂停保护、租约在最后心跳之后被接管时保留继任者票据/会话，以及内部检查的数据库/路由归属。实际 Cloudflare 上传、命名服务绑定与 HTTPS/Chromium 验收另行记录，不能用回调替身结果代替。

本地仅编辑源码及检查差异、JavaScript/JSON 语法；依赖安装、类型检查、测试、构建、部署和实际数据写入全部在 Cloudflare。原计划的生产开关保持关闭；C 的后台验收不启用供应商生产、公开内容或千站推广。

当前入口仍固定 P1 的已批准测试资源。完整 `site:provision` 命令/中央入口、多站分组清单管理、部署纠偏命令、其余运维命令以及 P1 剩余功能、P2–P5 均继续按执行计划完成。
