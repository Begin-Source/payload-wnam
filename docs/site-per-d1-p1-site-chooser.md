# P1 中央站点选择入口

完整目标仍为[一站一 D1 执行方案](site-per-d1-execution-plan.md)。本页记录中央站点选择界面和只读目录接口，不替代 P1 或完整计划验收。

## 员工流程

中央后台首页的“我的网站”显示当前员工获明确授权的网站、站点 ID、角色和运行状态。员工可按名称或稳定 ID 查找网站，点击“进入网站”后提交原生 POST 表单，沿用中央 60 秒单次票据和站点 host-only Cookie 交接。暂停、迁移、准备中或停用的站点不提供可用进入按钮；中央签发和站点请求仍独立执行权限检查，禁用按钮不是安全边界。

界面沿用 Payload 原生按钮和主题变量，以列表显示站点，支持手机换行、键盘提交、分页、加载、无授权、无匹配结果、会话失效和失败重试状态。进入动作有提交状态，浏览器历史返回后恢复可操作。

## 数据与权限

- `GET /auth/sites` 只挂载在独立中央应用，响应 `private, no-store`，只接受 `q` 和 `after` 参数。
- 使用真实中央 Payload JWT 提取的原会话，查询前后检查原会话有效期、撤销和账号锁定。API key、自动登录或调用者传入的员工 ID 不能替代该身份。
- 根据 `site_runtime_access` 中的明确员工授权读取中央注册表和中央站点名称；中央超级管理员角色本身不代表具有全部站点授权。
- 每页最多 50 个结果，读取第 51 条用于判断下一页，以稳定站点 ID 分页。名称/ID 搜索使用绑定参数和字面量匹配，不把用户输入当作 SQL 模式。
- 只返回 `siteId`、名称、角色和运行状态，不返回数据库 ID、binding、分组、凭据或会话。
- 查询只访问中央 D1。授权表通过显式 `migrateSiteControl` 增加 `(user_id, site_id)` 索引；没有请求期迁移，也不扫描各站 D1。
