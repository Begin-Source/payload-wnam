# P1 固定引用数据投递日志

状态：中央侧投递意图、机器领取、重试、死信和回执协议已经部署；实际 Cloudflare Queue 生产者/消费者、站点接收后写入候选区及后台操作界面尚未接通，因此本项仍未验收完成。

## 已实现边界

- `site_data_deliveries` 只保存固定的 `master`、`config` 或 `asset` 引用、目标站点、路由版本、Worker 分组和能力摘要。原始能力值不写入 D1。
- 经理请求投递前后都核验中央登录会话和实时站点权限，并在写入时重新核对注册表中的当前路由和分组。同一 `operationId` 只允许完全相同的重试。
- 私有机器 RPC 使用操作级能力领取固定引用，租约为 180 秒；相同租约重读不增加尝试次数，失败采用有界退避，最多 5 次后进入 `dead`。
- 成功回执必须匹配固定引用摘要，并且站点仍属于原路由版本和 Worker 分组。RPC 只返回 `denied` 或 `unavailable` 的有界错误，不返回中央 SQL、存储或凭据细节。
- 数据库触发器禁止改写投递身份、降低尝试次数、改变终态或删除历史。
